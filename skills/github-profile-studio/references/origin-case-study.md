# Case study: the profile this skill was distilled from

Profile: `github.com/Timcai06` (student developer; AI agents, ML observability, full-stack). Built July–October 2026 by the owner with AI coding agents, across 40+ commits and many review rounds. Read this to understand *why* the rules in this skill exist. **Do not reuse its look** (pixel-night backdrop, VS Code-style editor art, grey-only emphasis). Those came from this owner's identity and taste.

Evidence labels: **[commit]** = git history, **[review]** = the owner's recorded feedback during design sessions, **[inferred]** = our reading of the evidence, not stated by the owner.

## What the final page does

1. Hero: name + one-line roles, contact badges (the blog badge uses the site's own logo mark, not a stock icon). [commit]
2. A signature illustration: a calm pixel-art night plate behind an editor window whose `about.ts` holds the person's real focus, projects and stack. The file tree mirrors the page's own sections. [commit]
3. Bilingual intro (English + Chinese), fully visible, and a short "Now" note in a blockquote. [commit, review]
4. Four numbered chapters as centered `<h1>` openers (index, Chinese title, English subtitle): Featured work → Code in motion (a series) → Toolbox → More. [commit]
5. Lead projects as two-up cards; featured projects as image-left/text-right rows; each card is a generated SVG (editor window rendering the project's README, stack chips, a terminal panel with two real quick-start commands quoted from the repo). [commit]
6. A creative series framed as a *series* (statement first), with each work as its own card and key visual composed from real frames. [commit, review]
7. Toolbox as one light/dark SVG pair with six grouped cells; icons vendored locally, not hotlinked. [commit]
8. Archive and mathematical-modeling figures in folds; figures laid out as a full-width lead plus legible pairs. [commit, review]
9. A footer terminal that bookends the hero, an invitation line, grey `<kbd>` contact buttons. [commit]

Everything visual is generated by four Python scripts from JSON configs. Raw screenshots stay git-ignored. Configs store file names, not absolute paths. [commit]

## Where the quality actually came from

Not from the screenshots alone, and not from the pixel look. Five things worked together. These transfer; the look does not.

1. **One visual grammar across the page.** Every generated card, the hero, the toolbox and the footer share the same frame logic, label style and type roles. Real screenshots and generated SVGs sit in the same family.
2. **Each project's own content inside the grammar.** Every card renders that project's real README text, its real stack, two real commands from its README, and a mark taken from its domain. No two cards say the same thing.
3. **Hierarchy with different treatments per layer.** Identity hero → lead projects as two-up cards → featured projects as image-left rows → a series with its own statement layer above work cards → toolbox as one composed image → archive and figures in folds. Each layer looks different, so the reader always knows where they are.
4. **Rhythm between layouts.** Wide, two-up, rows, a single wide card, a grid, folds, a closing bookend. The page never repeats one block shape for long.
5. **Real work and original assets combined.** Real frames, real site screenshots and real paper figures carry the proof. Generated assets carry identity and structure (the editor scene encodes the actual projects and stack). Neither alone would have worked.

## Working practices that made it good

- The owner did all visual acceptance. Agents reported facts (sizes, DOM checks, sanitizer results) and did not declare things beautiful.
- Every round ended with a GitHub Markdown API render check (`gh api markdown`), not just a local preview.
- Nothing was pushed without an explicit "push".
- Process files (prompts, delivery notes, candidate frames) were cleaned out, and asset READMEs were rewritten as current-state maintenance docs.
